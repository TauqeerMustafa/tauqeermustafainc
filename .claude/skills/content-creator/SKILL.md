Proven structures for every content type — in `references/content_frameworks.md`:

- **AIDA** — Attention → Interest → Desire → Action (ads, landing pages)

- **4Ps** — Promise → Picture → Proof → Push (sales copy)
- **STAR** — Situation → Task → Action → Result (case studies)

## Writing by Format

### Blog Post (long-form)

```
1. Hook (first 2 sentences — make the reader feel the problem)
2. Context (why this matters now)
3. Main argument / thesis
4. 3–5 supporting sections with subheads
5. Practical takeaway / how-to
6. Closing CTA
```

SEO checklist per post:
- [ ] Primary keyword in H1, first 100 words, meta description
- [ ] Secondary keywords in H2s
- [ ] Internal links to ≥ 2 related pages
- [ ] External link to authoritative source
- [ ] Alt text on all images
- [ ] Meta description 150–160 characters

### Social Media

**LinkedIn post structure:**
```
Line 1: Bold hook (the scroll-stopper)
[blank line]
Lines 2–6: Context / story
[blank line]
Lines 7–10: Insight / lesson
[blank line]
CTA: question or link
#3–5 hashtags
```

**Twitter/X thread:**
```
Tweet 1: The hook — bold claim or surprising fact
Tweet 2–n: One idea per tweet, build on the last
Last tweet: Summary + CTA
```

### Email Newsletter

```
Subject line:  ≤50 chars, curiosity gap or clear benefit
Preview text: 90–140 chars, extends the subject
---
Opening: 1–2 sentences, personal or timely
Body: one core idea (not five), 200–400 words
CTA button: one action, verb-first ("Read the guide")
P.S.: the second-most-read element — use it for a bonus link
```

Subject line formulas:
- `[Number] ways to [outcome]`
- `Why [common belief] is wrong`
- `The [thing] nobody talks about`
- `You asked. Here's the answer.`
- `[Name], did you see this?`

### Landing Page Copy

```
Above fold:
  H1: outcome promise (what the user gets)
  Subhead: who it's for + how it works (one sentence)
  CTA: first button (primary action)

Social proof band: logos or stat strip

Problem section: name the pain in the user's words

Solution section: your product as the bridge

Feature → Benefit → Proof: 3–4 key features, each with a user benefit and a proof point

Testimonials: real quotes, full name + role + company

Pricing: anchor high, highlight recommended tier

FAQ: 5–7 objection killers

Final CTA: repeat the above-fold CTA
```

## Voice and Tone Guide

| Situation | Tone | Avoid |
|---|---|---|
| Blog / thought leadership | Confident, specific, opinionated | Hedging, jargon, passive voice |
| Social | Conversational, punchy | Corporate speak, emoji overload |
| Email | Personal, direct, one-idea | Long paragraphs, multiple CTAs |
| Landing page | Benefit-first, urgent, credible | Feature lists without benefits |
| Case study | Story-driven, evidence-based | Vague claims without numbers |

## SEO Content Workflow

1. **Keyword research** — target one primary keyword per page; 3–5 secondary keywords
2. **Search intent** — match the format to what the SERP shows (list post vs. guide vs. tool)
3. **Outline first** — H1 → H2s → H3s before writing a word
4. **Write to humans** — keyword density is a byproduct, not a target
5. **E-E-A-T signals** — Experience, Expertise, Authoritativeness, Trust (author bio, sources, date)
6. **Internal linking** — connect to pillar pages and related posts
7. **Update cadence** — refresh top posts every 6–12 months

## Common Pitfalls

- **Writing for everyone** — pick one reader, speak to them
- **Burying the lede** — state the value in the first sentence
- **Feature copy** — always translate features to user outcomes
- **Passive voice** — "the report was written" → "we wrote the report"
- **No CTA** — every piece needs one next step for the reader
- **Inconsistent voice** — document your brand voice and review against it
